# AGE-155 Windows setup boundary

The existing POSIX writer uses `fcntl`, directory-relative descriptors and no-follow opens; those calls are unavailable on Windows. Two designs were compared: a path-only adapter with repeated checks, and a Windows handle adapter. Path-only checks leave a junction replacement race. The handle adapter instead pins each directory from the volume root without delete sharing, rejects reparse points, uses an exclusive persistent lease, compares the current file before publication, and renames an exclusively created file by handle within its verified parent.

The Windows adapter retains the existing writer protocol and typed outcomes. For an existing configuration, it verifies the replacement owner and copies the DACL before publication; it fails closed if these operations are unavailable. File writes in one directory share a lease derived from the directory's volume and file identity, so case and short-name aliases cannot acquire separate leases. Staging and recovery continue to use persistent records and file identity. Linux and macOS continue to use the existing POSIX implementation.

The lease serializes participating setup writers. As with the existing writer, an unrelated program that does not participate in the lease can still change a destination between the comparison and replacement. A crash immediately after a temporary entry is created but before its identity is recorded can leave that isolated entry for manual inspection; the writer must not delete an unverified entry. Windows-specific execution must be verified on a Windows runner; local Linux checks alone do not establish Windows behavior.
