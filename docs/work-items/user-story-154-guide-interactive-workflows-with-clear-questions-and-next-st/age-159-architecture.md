# AGE-159 architecture

Two candidates were compared: an elicitation reducer embedded in the current storyboard visit, or a separate event log projected into workflow state. The event log would add a second state owner and persistence contract. The selected design puts only the current method selection and review phase in the existing discovery snapshot. The two requested independent sketches were grounded in supplied contracts because the harness blocked their workspace reads; the implementation was checked against the actual local source.

`reduceElicitation` returns immutable selection data or an explicit failure. It does not run methods or select a workflow target. `nextDiscovery` checks session and occurrence, composes that reducer only at the elicitation node, and remains the sole owner of workflow navigation. Pause wraps the same state; proceeding requires an explicit completed interaction. The host obtains available method IDs from the existing elicitation catalog, normalizes user choices through the existing question boundary, performs method work and displays the result. Applying or rejecting it is an explicit event. There is no additional state store.
